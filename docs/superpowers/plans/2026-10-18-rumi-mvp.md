# Rumi MVP (Release 01) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Construir la web responsive de Rumi (HU-01 a HU-07) con datos simulados en el navegador, probada y subida a `LuisMa4/Project-Rumi`.

**Architecture:** SPA de React con `HashRouter`. Las páginas solo llaman a `src/services/*` (asíncronos), que persisten en `localStorage` (claves `rumi:*`) mediante `storage.ts` → `db.ts`. La sesión vive en `AuthContext`. Un solo componente de navegación cambia de barra inferior (<768 px) a menú lateral (≥768 px) solo con CSS.

**Tech Stack:** TypeScript (strict), React, Vite (`react-ts`), react-router-dom (HashRouter), CSS Modules, lucide-react, @fontsource (Bricolage Grotesque, DM Sans), Vitest, React Testing Library, @testing-library/user-event, jsdom.

**Spec:** `docs/superpowers/specs/2026-10-18-rumi-mvp-design.md`

## Global Constraints

- Todo el texto de la UI en español, en sentence case. Mensajes de error exactos en la tabla de `validation.ts` (Task 3).
- Colores: exactamente los tokens de la sección 4 del spec, definidos en `src/styles/tokens.css`; ningún componente usa un hex fuera de ese archivo.
- Tipografía: títulos en `'Bricolage Grotesque'`, texto en `'DM Sans'` 16 px, vía `@fontsource/*` (sin Google Fonts).
- Breakpoint único: `768px`. La columna de contenido mide como máximo `640px`.
- Ninguna página ni componente toca `localStorage`; solo `src/services/storage.ts`.
- Los servicios devuelven `Promise` y nunca exponen `passwordHash`.
- Límites: contraseña ≥ 8; publicación 1–500; bio ≤ 300; mensaje 1–1000; precio > 0.
- Error de login único: `Correo o contraseña incorrectos`.
- Las listas que esperan a un servicio muestran `Cargando…` mientras tanto.
- Respuesta automática del chat: entre 1500 y 2500 ms.
- `vite.config.ts` usa `base: './'`.
- Sin dependencias fuera de las listadas en Tech Stack (más las de la plantilla de Vite).
- Commits en `main` local al final de cada tarea, con el trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. El push solo ocurre en la Task 14.
- Comandos de verificación: `npm test` (= `vitest run`), `npm run lint`, `npm run build`.

## Review Focus

1. Correo con mayúsculas o espacios (`"  Ana@Mail.COM "`): el registro y el login lo normalizan (trim + minúsculas) y lo encuentran → test en Task 4.
2. Texto solo con espacios en publicaciones y mensajes: se rechaza como vacío, no se guarda en blanco → tests en Tasks 6 y 7.
3. `localStorage` con JSON corrupto o bloqueado (modo privado): la app no se cae; se usa el valor por defecto o la memoria → tests en Task 2.
4. Sesión que apunta a un usuario que ya no existe (por ejemplo, después de restablecer la demo): `getCurrentUser()` devuelve `null` y limpia la sesión → test en Task 4.
5. Ids inválidos o ajenos en la URL (`/perfil/nope`, `/mensajes/nope`, una conversación de la que no eres parte): se muestra "No encontramos este perfil o conversación" → tests en Tasks 7, 12 y 13.

### Task 3: Validaciones y utilidades de texto y formato

**Files:**
- Create: `src/services/validation.ts`, `src/utils/text.ts`, `src/utils/format.ts`
- Test: `src/services/validation.test.ts`, `src/utils/text.test.ts`, `src/utils/format.test.ts`

**Interfaces:**
- Produces:
  - `MSG`, un objeto con el texto exacto de cada error:

    | Clave | Texto |
    |---|---|
    | `requerido` | `Este campo es obligatorio` |
    | `email` | `Ingresa un correo válido` |
    | `emailDuplicado` | `Ya existe una cuenta con este correo` |
    | `password` | `La contraseña debe tener al menos 8 caracteres` |
    | `fechas` | `La fecha de salida debe ser posterior a la de llegada` |
    | `bio` | `La biografía puede tener hasta 300 caracteres` |
    | `postVacio` | `Escribe algo para publicar` |
    | `postLargo` | `La publicación puede tener hasta 500 caracteres` |
    | `precio` | `El precio debe ser mayor que 0` |
    | `mensajeVacio` | `Escribe un mensaje` |
    | `mensajeLargo` | `El mensaje puede tener hasta 1000 caracteres` |
  - `validateProfileFields(f: Partial<RegisterInput & ProfileChanges>): Record<string, string>`: valida solo las claves presentes. Los textos obligatorios usan trim y dan `requerido`; también aplica `email` (regex `^[^\s@]+@[^\s@]+\.[^\s@]+$`), `password` (< 8), `bio` (> 300) y, si vienen ambas fechas, `fechas` en `fechaSalida` cuando `fechaSalida <= fechaLlegada`. Una fecha presente pero vacía da `requerido`.
  - `normalizeEmail(e: string): string` (trim + minúsculas).
  - `text.ts`: `normalizeText(s: string): string` (trim, minúsculas, sin tildes vía NFD) e `includesNormalized(haystack: string, needle: string): boolean` (si `needle` normalizado es `''` devuelve `true`).
  - `format.ts`, todas con fechas ISO `YYYY-MM-DD` leídas como fecha local (`new Date(y, m - 1, d)`) y meses abreviados en español sin punto:
    - `formatRelative(iso: string, now = new Date()): string` → `ahora` (< 1 min), `hace N min`, `hace N h` (< 24 h), `ayer` (< 48 h), si no `d mmm`.
    - `formatDate(iso: string): string` → `3 feb 2027`.
    - `formatDateRange(desde?: string, hasta?: string): string` → `feb–jul 2027` (mismo año), `dic 2026–feb 2027`, `desde feb 2027` (solo desde) o `''`.
    - `formatPrice(precio: number, moneda = 'EUR'): string` → `Intl.NumberFormat('es', { style: 'currency', currency: moneda, maximumFractionDigits: 0 })`.
